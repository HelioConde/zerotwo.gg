# ZeroTwo.gg — Auditoria SEO (9 de outubro de 2026)

## Escopo e diagnóstico

Site público: https://helioconde.github.io/zerotwo.gg/

Páginas indexáveis: a home + 10 páginas HTML temáticas (`estatisticas-lol`, `riot-id`, `maestria-lol`, `historico-lol`, `como-funciona`, `rank-lol`, `arena-lol`, `lol-stats-tracker`, `sobre`, `glossario-lol`). Todas têm title/description/canonical próprios e JSON-LD.

### Principais oportunidades encontradas
- A home servia somente um elemento `<div id="root"></div>` no HTML inicial: os links dos guias e o H1 só existiam após execução do bundle React. Isso não impede necessariamente o Google de renderizar a página, mas cria uma dependência adicional de JavaScript e não ajuda crawlers que não executam JS.
- Páginas estáticas tinham Open Graph básico, mas não possuíam Twitter/X cards, locale e texto alternativo da imagem de compartilhamento.
- Não havia verificação automatizada dedicada a metadados e integridade de links, canonical e sitemap.
- Sitemap existente tinha datas anteriores, prioridades e frequências que não são sinais de ranqueamento; corrigimos a data de alteração **somente da home**, que recebeu conteúdo HTML novo.
- Site hospedado como **projeto** no GitHub Pages, sob o caminho `/zerotwo.gg/`. O arquivo em `/zerotwo.gg/robots.txt` é um arquivo público útil como referência, mas **não é o robots.txt efetivo do host**; robôs procuram `https://helioconde.github.io/robots.txt`, que não pode ser configurado diretamente por este repositório de projeto.

## Correções desta auditoria
1. Home com fallback progressivo em HTML: H1, resumo do produto, links de navegação para os 10 guias e explicação de metodologia. Fica visível apenas quando o JavaScript está indisponível; o React substitui o fallback quando inicializa, evitando duplicação de conteúdo na tela.
2. `index.html`: title mais conciso, mantém canonical original, JSON-LD WebApplication/Organization/WebSite e Open Graph; adicionado link ao sitemap.
3. Dez páginas estáticas: Twitter/X summary-large-image, title, description, image, alt e Open Graph locale/alt.
4. `public/sitemap.xml`: inventário de 11 URLs canônicas, sem URLs de jogadores por parâmetro e sem `changefreq`/`priority`; `lastmod` atualizado somente onde o conteúdo foi alterado.
5. `scripts/audit-seo.mjs`: checagem sem dependências externas de title e description, canonicals e OG URLs, tags essenciais, um H1 por página, links navegáveis que apontam para arquivos reais, JSON-LD parseável, assets OG existentes, sitemap com URLs únicas e fallback inicial.
6. GitHub Actions: `npm run audit:seo` integra o pipeline de deploy e pode impedir que erros de SEO sejam publicados. Playwright inclui teste sem JavaScript e confirma que a versão com React substitui a página fallback.

## Cuidados com indexação e governança

- As URLs `?player=Nome%23TAG&server=br1` mostram perfis dinâmicos com dados consultados. A página inicial mantém a canonical para a home. **Não colocar milhares de URLs de jogadores no sitemap sem HTML único e pré-renderizado**, verificação de consentimento/privacidade e análise da finalidade da indexação.
- Não publicar métricas como MMR inventado, resultados em tempo real ou afirmações sem dados Riot. A linguagem deve diferenciar fatos e interpretações.
- A ausência de `robots.txt` no host-root **não significa que o site esteja bloqueado**. As tags canonical e meta robots nos documentos e o sitemap continuam sendo úteis.
- Site sob domínio compartilhado `github.io`: se, no futuro, mudar para domínio próprio, configurar o robots.txt no **host raiz**, redirecionamentos 301 das URLs antigas quando possível e canonicals/sitemap atualizados sem duplicar conteúdo.
- HTML inicial do app não é equivalente a SSR/prerender individualizado; a Riot Life permanece interativa e exige JavaScript.

## Search Console — execução pendente

No momento da auditoria, o conector GSC Wizard lista propriedades da Ofertamática, mas **nenhuma propriedade do ZeroTwo.gg**. Para obter impressões, cliques, CTR, posições e status real de indexação:
1. Criar/verificar uma propriedade **Prefixo do URL** para `https://helioconde.github.io/zerotwo.gg/` no [Google Search Console](https://search.google.com/search-console).
2. Verificar a titularidade pelo método aceito pelo Google. Já existe uma página de verificação HTML e meta verification no projeto, mas será preciso conferir qual token a propriedade recém-criada espera.
3. Enviar `https://helioconde.github.io/zerotwo.gg/sitemap.xml` no relatório Sitemaps.
4. Inspecionar a home e as landing pages principais pelo relatório de inspeção de URL. Validar a versão renderizada, canonical escolhido pelo Google, URLs descobertas e indexação.
5. Medir termos de busca, CTR e páginas com impressões durante 4 a 6 semanas antes de priorizar novos temas. SEO não garante posição 1 nem indexação imediata.
